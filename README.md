# universal-cnc
Официальный сайт программы "Универсал — система ЧПУ"

## Раздел «Шпиндели»

- Данные всех шпинделей — один файл `data/spindles.js` (массив `SPINDLES`).
- `spindle-changsheng.html` — список всех шпинделей (по брендам); `spindles/<slug>.html` — отдельная страница модели.
- Обе части и записи в `sitemap.xml` генерируются командой `node scripts/build-spindles.js` (страницы руками не правим).
- Новый шпиндель: добавить объект в `SPINDLES` (уникальные `id` и `slug`), фото — в `images/`, запустить скрипт, закоммитить.
- Фото модели: массив `photos` (пути от корня сайта, первое фото — главное). Старое поле `img` тоже поддерживается: главное фото = `photos[0]` или `img`. В списке и в marketplace показывается только главное фото.
- Дополнительное фото к существующей модели (другой ракурс, детали): положить файл в `images/` и добавить путь в `photos` этой модели, например:

      photos: [
        'images/tongsheng-thd80-2.2c-ru.jpg',
        'images/tongsheng-thd80-2.2c-ru-2.jpg'
      ]

  Затем выполнить `node scripts/build-spindles.js` и закоммитить файл фото, данные и сгенерированные страницы. На странице модели появится галерея: стрелки, миниатюры, счётчик «1 / N», пролистывание пальцем и полноразмерный просмотр по клику.
- Доп. информация по модели: `description` (абзацы описания), `applications` (применение), `notes` (`{date, text}` — сведения из писем), `clarify` (что уточняется), характеристики — в `specs`.
- Скрипт проверяет дубли id/slug, наличие каждого файла из `photos`, отсутствие дублей в массиве и отсутствие иероглифов.

## Артикулы товаров

У каждого товара сайта есть постоянный **артикул** — 5 цифр. По нему удобно ставить задачи («арт. 20007 — поправь вес») и спрашивать о товаре покупателям.

| Группа | Что | Где хранится |
|---|---|---|
| `1xxxx` | станки и оборудование (`10001` — ЧПУ 3040/4060) | `data/catalog.js` → `MACHINES` |
| `2xxxx` | шпиндели | `data/spindles.js` → поле `sku` |
| `3xxxx` | комплектующие, инструмент, расходники, ПО, лазеры, частотники, приводы, контроллеры | `data/catalog.js` → `CATALOG` (без своей страницы) и `data/products.js` → `PRODUCTS` (с карточкой `products/<slug>.html`) |

Правила:
- Артикул хранится явным полем `sku` и **не зависит от порядка** товаров — при добавлении, перестановке и сортировке он не меняется.
- Артикул никогда не меняют и не переиспользуют (даже если товар снят с продажи).
- **Выбывшие артикулы** (не использовать повторно): `20029`, `20030`, `20031` — обобщённые карточки шпинделей без фото, убраны 20.11.2026 как дубли. Они перечислены в `SPINDLES_RETIRED` в `data/spindles.js` (с моделью-заменой): скрипт учитывает их при выборе следующего номера, на старых адресах генерирует страницы-переадресации, а корзина переносит такой товар на модель-замену (20029 → 20002, 20030 → 20001, 20031 → 20011). В `docs/articles.csv` они помечены «Выбыл».
- Новый шпиндель: поле `sku` можно не писать — `node scripts/build-spindles.js` сам впишет в `data/spindles.js` следующий свободный номер (наибольший `2xxxx` + 1). Новому товару в `data/catalog.js` — вручную следующий свободный номер своей группы.
- Скрипт сборки проверяет: у всех товаров есть артикул из 5 цифр, группа соответствует типу, дублей по всему сайту нет.
- Таблица всех артикулов — `docs/articles.csv` (артикул; тип; название; id; ссылка), генерируется скриптом, руками не правится. Открывается в Excel.
- На сайте артикул показан на карточке marketplace, в списке и на странице шпинделя, на странице станка, в корзине и в тексте заказа; кнопка «Копировать» копирует его в буфер. В разметке schema.org Product это поле `sku`.
- Поиск на marketplace находит товар по артикулу; прямая ссылка: `marketplace.html?q=20001`.

## Версии общих файлов (защита от старого кэша)

GitHub Pages отдаёт файлы с заголовком `Cache-Control: max-age=600`, поэтому браузер может до 10 минут (а при открытой вкладке и дольше) показывать старые цены из ранее скачанного `data/spindles.js`. Поэтому общие файлы подключаются с меткой версии:

    <script src="data/spindles.js?v=1f03f879"></script>
    <script src="data/catalog.js?v=096d063c"></script>
    <link rel="stylesheet" href="style.css?v=e624a654">

Правила:
- Метка `?v=` — первые 8 символов sha256 **содержимого** файла. Её проставляет `node scripts/build-spindles.js` во всех `.html` сайта (кроме `docs/`, `api/`, `scripts/`, `mistral-advanced-bot/`): изменился файл — изменилась метка — браузер скачивает новый файл; не изменился — кэш продолжает работать.
- Под метки попадают `data/spindles.js`, `data/catalog.js`, `data/products.js` и `style.css` (список `VERSIONED` в скрипте). Новый общий файл с данными или стилями — добавить в этот список.
- После любой правки `data/spindles.js`, `data/catalog.js`, `data/products.js` или `style.css` (цены, товары, стили) обязательно запустить `node scripts/build-spindles.js` и закоммитить изменённые страницы вместе с данными. Метки руками не правим; новую страницу можно подключать без метки — скрипт допишет её сам.

## Служебный генератор карточек

Раньше был открытой страницей `private-cnc-tool-7x9k.html` с паролем в коде — страница удалена с сайта. Теперь это serverless-функция Vercel `api/card-tool.js`: https://universal-cnc.vercel.app/api/card-tool. Пароль проверяется на сервере и хранится только в переменной окружения Vercel **`CARD_TOOL_PASSWORD`** (в репозитории его нет). Без этой переменной инструмент выключен.

## Товары с карточками (`data/products.js`)

- Каждый товар: `id` (ключ корзины), `sku` (следующий свободный `3xxxx`, общий счёт с `CATALOG`), `slug`, `cat` (ключ из `PRODUCT_CATS`), `title`, `short`, `price` (обязательно, без «по запросу»), `img` (пусто — «Фото уточняется»), `specs` (пары «название — значение», только проверенные данные), `description`.
- `node scripts/build-spindles.js` создаёт `products/<slug>.html` (разметка Product), добавляет товары в sitemap (`products:start/end`), ItemList на `marketplace.html` и `docs/articles.csv`. Скрипт проверяет цену, категорию, дубли и отсутствие иероглифов.
- Новая категория: ключ и название в `PRODUCT_CATS` и кнопка `data-cat` в `marketplace.html`.
- Цены и источники — `docs/products-prices-2026-11.csv`.

## Языковые версии (`/en/`, `/kk/`, `/uz/`, `/hy/`, `/ka/`, `/ky/`)

Русский — основной язык, страницы остаются на прежних адресах. Переводы генерирует `scripts/build-i18n.js`
(он вызывается из `node scripts/build-spindles.js`, отдельно запускать не нужно):

- для каждого языка: главная, каталог с категориями, «Станки», «Оплата и доставка» (с той же формой онлайн-оплаты)
  и карточки всех шпинделей, станков и товаров из `data/products.js`;
- тексты интерфейса, категорий и названий характеристик — в `i18n/<язык>.json` (`ui`, `cats`, `catDesc`, `specLabels`);
- названия товаров и значения характеристик переводятся по словарю `glossary`/`units` из тех же файлов.
  Новый товар появится на всех языках сам. Если в его названии или характеристиках есть фраза, которой нет в словаре,
  сборка остановится и покажет её — добавьте перевод этой фразы во все шесть файлов `i18n/*.json`;
- на русских страницах генератор ставит переключатель языка (маркеры `LANG:START/END`) и `hreflang`
  (маркеры `HREFLANG:START/END`); в `sitemap.xml` — языковые адреса (блок `i18n:start/end`) и `xhtml:link`;
- выбор языка запоминается в браузере (`localStorage.siteLang`); переадресация только с русской главной и только
  для человека, который сам выбрал другой язык (роботов поисковиков не переадресует);
- в конце сборки ссылки на `index.html` заменяются чистыми адресами (`../index.html` → `../`, `en/index.html` → `en/`),
  чтобы у главных страниц был один адрес, совпадающий с `canonical` (иначе поисковики видят дубли title/description).
  `program/Mach3.html`, `equipment/cnc-3040.html`, `knowledge/` и `equipment-data/` не трогаются. Новые страницы лучше сразу
  писать со ссылками вида `../`, а не `../index.html`;
- цены везде в рублях; в долларах — только у шпинделей, где задан `priceUsd`;
- корзина и чат пока только на русском (ссылка «Корзина» ведёт на `cart.html`).

Переводы на казахский, узбекский, армянский, грузинский и киргизский сделаны машинно — их стоит проверить носителю языка.
